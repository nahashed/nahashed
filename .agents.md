# Profile repository

This repository is the public GitHub profile for `nahashed`. The profile text is
English. Discuss maintenance with the owner in Russian. Do not invent biography,
employment, experience, or proficiency claims. Keep existing contacts and
avatar.

`AGENTS.md`, `CLAUDE.md`, and `GEMINI.md` are symlinks to this file. Edit this
source.

## Structure

- `README.md` is the profile entry point, not developer documentation.
- `scripts/profile.ts` collects GitHub data, detects technologies, and renders
  SVGs.
- `assets/stack-light.svg` and `assets/stack-dark.svg` are generated public
  output.
- `tests/profile_test.ts` uses synthetic data only and no network.
- `.github/workflows/check.yml` runs checks without private-data secrets.
- `.github/workflows/profile.yml` updates from trusted `main` on GitHub-hosted
  runners.
- `docs/maintenance.md` covers operation and token renewal.

## Privacy and reliability

Use TypeScript with Deno and built-in APIs, without npm or external
dependencies. Never execute commands, install dependencies, follow download
URLs, or import code from inspected repositories. Never log request URLs, API
bodies, exception details, manifests, private names, or tokens. Keep all raw API
data in memory. Publish only aggregate languages and allowlisted technologies.

Collect the complete dataset before writing either SVG. Errors must fail the run
without publishing partial results. Do not add timestamps, random output,
counters, or keepalive commits. Do not attach workflow artifacts containing
collected data. Never pass `PROFILE_READ_TOKEN` to pull-request workflows or
third-party services.

`TOPICS` maps approved repository topic slugs to public technology labels.
Expand this allowlist for new technology topics. Never output arbitrary topic
strings, including from public repositories. Deduplicate aliases and keep topics
visually separate from technologies detected in manifests.

## Changes and checks

Edit layout and colors in `render`, then regenerate both assets using the
trusted update workflow. The accent is `#ed2207`. Keep dark/light parity, static
SVGs, readable contrast, and accessible titles. Do not manually fabricate a
first snapshot.

Extend `detectTechnologies` and `TECHNOLOGIES` together. Use exact dependency
names or well-defined registry URLs and launch configuration, never
descriptions, keywords, private package names, or repository names. Add a
focused synthetic unit test.

Run `deno task check` and `deno task test`. Inspect both SVGs after layout
changes. Review `git diff` for privacy before committing. Do not modify other
repositories, profile identity, or repository visibility. Never save a token
locally or in chat.
